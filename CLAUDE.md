# CLAUDE.md

`shiny.val.tools` — R package producing per-feature validation artifacts
for Shiny apps in pharma/GxP contexts, including modern rhino apps using
`box`. Full design lives in `specs/`. Start with `specs/00-overview.md`,
then `specs/05-public-api.md` for the suggested implementation order.
`specs/06-testing.md` covers the test-surface / scaffolding /
verification-traceability layer.

## Workflow: TDD, green check before moving on

For every meaningful increment — one exported behavior, one bug fix, one
new warning code:

1.  Write a failing `testthat` test under `tests/testthat/`.
2.  Implement the minimum to pass.
3.  Run `devtools::check()` (or `R CMD check`). Fix every error,
    warning, and note. Never move on without a clean check.

Test fixtures are small hand-built Shiny apps in `inst/extdata/`, each
exercising a specific pattern (modules,
[`box::use`](https://klmr.me/box/reference/use.html), hybrid imports,
dynamic IDs, conditional
[`source()`](https://rdrr.io/r/base/source.html)). Add a fixture before
the test that needs it.

For manual end-to-end checks against a real-world app, run against
`D:\repos\shiny.explore`. That app is not part of the automated test
suite — it is the user’s sanity-check substrate when inspecting how
artifacts look in practice.

## Specs are the source of truth

If implementation must diverge from a spec, update the spec in the same
commit — never silently. If a spec is ambiguous, ask before guessing.
The specs went through several rounds of pushback; treat them as
deliberate.

## Stability contracts

Don’t break these without a `schema_version` bump and migration note in
the relevant spec:

- **`inventory.json`** (spec 03) is pinned at `schema_version: "1.0"`.
  Additive changes only within v1; never remove or rename fields.
  Downstream pharma tooling reads this. Same rule for
  `test_surface.json` and `traceability.json` (spec 06), both pinned at
  `"1.0"`.
- **Warning codes** — `SVT-W001..010` graph (spec 01), `SVT-W101..105`
  features (spec 02), `SVT-W201..206` inventory (spec 03),
  `SVT-W301..311` testing (spec 06) — are stable identifiers. Don’t
  renumber, don’t reuse retired codes. New codes append to the relevant
  range.
- **Determinism** — same source + manifest + package version →
  byte-identical artifacts. Hash-derived node IDs, sorted outputs,
  seeded layouts. Add a determinism test where it matters.

## Don’t reinvent

Specs already chose dependencies deliberately:
[`renv::lockfile_read`](https://rstudio.github.io/renv/reference/lockfiles.html)
for recorded package versions (spec 03 — discovery is *not* delegated to
[`renv::dependencies`](https://rstudio.github.io/renv/reference/dependencies.html),
and `pak` is deliberately not a dependency), `testthat` for tests, `cli`
for messages, `tibble` for tables, `visNetwork` for rendering, base R
[`parse()`](https://rdrr.io/r/base/parse.html) + a hand-rolled visitor
for AST. Don’t substitute without updating the spec.

## Behavioral discipline

- **Think before coding.** State assumptions; ask if a spec is unclear;
  surface tradeoffs. Don’t pick silently between interpretations.
- **Simplicity first.** Minimum code to pass the test. No speculative
  abstractions, no flexibility for callers that don’t exist. If you
  write 200 lines and it could be 50, rewrite it.
- **Surgical edits.** Touch only what the failing test requires. Note
  unrelated dead code; don’t delete it.
- **Comments only when the WHY is non-obvious.** Don’t restate the code.

These bias toward caution over speed. For trivial changes, use judgment.

## What this package does not do

Full list in `specs/00-overview.md` non-goals; repeated here to prevent
drift:

- Validate the app or its packages — we produce evidence; `riskmetric` /
  `val.meter` score; humans validate.
- Write the app’s tests — we derive the test surface, scaffold the
  harness, and map existing tests to features; assertions and expected
  values are human work, permanently (spec 06). We never run the app or
  its tests.
- Run the app — static analysis only, no `reactlog`.
- Trace beyond R — no JS handlers, no `www/`, no `htmlwidgets`
  internals.
- Diff across versions; multi-app analysis; auto-narrative
  documentation; monolithic reports.
